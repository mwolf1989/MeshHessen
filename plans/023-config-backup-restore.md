## Why this matters

Windows 1.7.3 adds "Backup / Restore configuration" in the Tools tab: one JSON file with owner, all config and module sections and all eight channels (including keys). It is offered before a firmware update and lets users set up a replacement device in one step. When the backup comes from a different node the security section (keys) is not restored, so identities are never cloned. The Mac can only export CSV lists.

Windows file layout (keep it — files should be exchangeable between both clients):
```json
{ "exportedAt": "<ISO 8601>", "nodeId": "!xxxxxxxx", "firmwareVersion": "2.x.y…",
  "myInfo": {…}, "metadata": {…}, "owner": {…},
  "config": [ {…}, … ], "moduleConfig": [ {…}, … ], "channels": [ {…}, … ] }
```
Each entry is the protobuf-JSON of a `Config` / `ModuleConfig` (one populated oneof each) / `Channel` / `User` / `MyNodeInfo` / `DeviceMetadata`. Unknown fields are ignored on import; `config` is required. Windows writes with default values included; proto-JSON field names are lowerCamelCase — check one line of the C# writer (`JsonFormatter` settings) for whether it preserves proto field names (snake_case); SwiftProtobuf's `init(jsonString:)` accepts both spellings.

Restore rules (Windows): `begin_edit_settings` → `set_owner` → every `set_config` → every `set_module_config` → every `set_channel` → `commit_edit_settings`; the session-key config is skipped; the **security** config is written only when the backup's `nodeId` equals the connected node; channel names are clamped to 11 UTF-8 bytes.

## Steps

### Step 1: File model (pure)
`ConfigBackupFile.swift`:
```swift
struct ConfigBackupFile {
    var exportedAt: Date; var nodeId: UInt32; var firmwareVersion: String
    var owner: Meshtastic_User?; var configs: [Meshtastic_Config]; var moduleConfigs: [Meshtastic_ModuleConfig]; var channels: [Meshtastic_Channel]
    init(snapshot: MeshConfigurationSnapshot, nodeId: UInt32, firmwareVersion: String, now: Date)
    func jsonData() throws -> Data
    init(jsonData: Data) throws              // tolerant: unknown keys ignored, `config` required
    func summary(connectedNodeId: UInt32, connectedFirmware: String) -> ConfigBackupSummary   // source node, versions, section names, isSameNode
    func apply(to current: MeshConfigurationSnapshot, connectedNodeId: UInt32) -> MeshConfigurationSnapshot
}
```
- Export: only sections whose "loaded" flag is set; never the session-key config. Build the outer JSON with `JSONSerialization` from per-proto `jsonString()` fragments.
- `apply`: start from `current`, overwrite owner (keep `current.owner.id`), each config/module present in the backup, and channels; **skip the security config when `nodeId != connectedNodeId`**; clamp channel names with `UTF8Limits.clamp(_, maxBytes: 11)` if plan 001's helper exists (else byte-truncate at a Character boundary locally).
- Errors: `enum ConfigBackupError: LocalizedError` (invalid file, missing config section).

**Verify**: `swift test --filter ConfigBackup` (Step 4 tests) → pass.

### Step 2: Protocol functions
```swift
func exportConfigurationBackup(progress: …) async throws -> ConfigBackupFile     // requestCompleteConfiguration(from: .local, …) → ConfigBackupFile
func restoreConfigurationBackup(_ file: ConfigBackupFile) async throws -> MeshConfigurationDiff
```
Restore = read the current snapshot (`original`), `updated = file.apply(to: original, connectedNodeId: myNodeId)`, then `saveCompleteConfiguration(updated, replacing: original, to: .local, …)`. This reuses the existing single-transaction diff write; sections identical to the device are simply not rewritten.

### Step 3: UI
`ConfigBackupSection` (added to `ToolsView` as a new section "Configuration backup", enabled only while connected):
- "Create backup…" → progress → `.fileExporter` with a JSON `FileDocument`, default name `node-<8 hex id>-<yyyyMMdd-HHmmss>.json`; caption: "The file contains channel keys and, for this node, its private key. Store it safely."
- "Restore backup…" → `.fileImporter` (`.json`) → summary sheet (source node, backup firmware vs. device firmware, sections contained; if a different node: "Security keys will not be restored.") → Confirm → restore → result message ("n sections written; the device will reboot.").
- Errors via `@State private var errorMessage: String?` + `.alert`.

### Step 4: Tests
`ConfigBackupTests.swift`:
- Round trip: snapshot with LoRa preset, a module setting and two channels (random PSK bytes) → `jsonData()` → `init(jsonData:)` → equal protos.
- Top-level keys are exactly those of the Windows layout; `nodeId` formatted `"!%08x"`.
- A hand-written Windows-style JSON using snake_case proto field names parses.
- `apply` with a different node id leaves `security` equal to the current snapshot; same node id replaces it.
- Missing `config` → throws; unknown top-level key → ignored.
- Channel name longer than 11 bytes is clamped.
